# Nostalgia

Nostalgia 是设计中的个人上下文组件，定义 Context 的身份、来源、修订与检索。当前没有运行服务、数据库适配器或 Hymio 集成。

## 用真实资料对照设计

本轮 Hymio 案例实际上传了[一份行程笔记](/examples/trip-notes.txt)，并在 iPhone 收到模型整理的三条核对事项，见[附件案例](../hymio/media)。这份资料适合解释 Nostalgia 未来的边界：笔记是输入内容，文件身份对应 Source，修改后的内容应形成 Revision，整理结果需要关联原文版本。

**当前实际运行的是 Hymio 的附件与对话链路，尚未经过 Nostalgia。** 下面的 Context 管理流程仍是设计，不能据此认为已有可部署的 Nostalgia 服务。

## 先看一个例子

你想让 Agent 参考一份不断修订的旅行计划。应用连接器读取文件，把内容及来源交给 Nostalgia；计划修改后形成新版本。之后检索返回相关内容，并说明来自哪个文件、哪个版本。

这是设计中的流程，尚没有可调用服务。Nostalgia 可以理解为 Context 收集与管理组件：连接器负责读取外部来源，它负责组织收到的信息，保留来源与版本，而不是抓取任意数据的通用爬虫。

## 先认识这些术语

| 术语 | 在这里是什么意思 |
| --- | --- |
| Context / 上下文 | Agent 可参考的资料与背景，例如计划、笔记或文件片段。 |
| Space / 空间 | 一组上下文的归属和权限范围。 |
| Source / 来源 | 信息来自哪个外部对象，例如某份文件及其版本。 |
| Revision / 修订 | 某条 Context 在某一时刻的不可变内容版本。 |
| Asset / 资源 | 上下文引用的图片、文件等二进制内容。 |
| Provenance / 派生关系 | 摘要等加工结果与原文版本的关联，便于追溯。 |
| Change feed / 变更流 | 按顺序列出的变更，让其他组件只同步新增和修改的内容。 |
| Embedding / 向量 | 用于语义检索的内容表示，是派生索引；当前尚未选择实现方案。 |
| Kit | 计划中的应用能力模块，保存该业务自己的权威数据；目前尚未集成。 |
| 存储适配器 | 把同一套接口接到不同数据库的内部实现，目前尚未实现。 |

## 预期边界

| 职责 | 归属 |
| --- | --- |
| 导入文件或同步外部来源 | Hymio / 应用连接器 |
| 保存权威业务事实 | 对应应用或 Kit |
| 表达上下文、来源与修订 | Nostalgia 设计 |
| 调度和执行 Agent 工作 | Oath |

设计区分 Context HTTP API 与内部存储适配器。未来不同数据库可以实现相同的权限、版本和 change feed 语义。目前尚未选择数据库或 embedding 方案。
