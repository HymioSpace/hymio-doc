# 多端互通

在 iPhone 上交代一件事，回到电脑继续追问；在手机上切换模型，Web 也使用同一个选择。Hymio 把对话、任务和账号偏好保存在同一后端，各端用适合自己的界面接入。

## 真实案例：手机列清单，电脑继续精简

准备一次两天的短途旅行。我们用独立演示账号在原生 iOS 应用发起打包清单请求，再在 Web 登录同一个账号继续处理。

1. **iPhone 发起**：在「对话」要求按证件、衣物、洗漱、充电四类列出清单。原生应用显示模型返回的中文清单。
2. **Web 接着问**：同一账号打开「对话」，可以看到刚才的请求与回复，接着发送「把刚才那份清单压缩成四行，每行不超过十二个字」。
3. **回到 iPhone**：无需复制内容或新建会话，手机收到 Web 上的追问和精简后的结果。

## 真实案例：在手机选模型，Web 读取同一选择

在 iPhone 的「我的 → 对话模型」把 `MiniMax-M2.7` 切换为 `MiniMax-M3`，再打开 Web 的「我的」。本轮实测两端都显示 `MiniMax-M3`，已有对话保留。这个选择影响之后发送的消息，不会重跑旧回复，也不自动更改媒体理解服务。

## 哪些内容可以接着用

| 功能 | iPhone 上怎么用 | 回到 Web / Desktop |
| --- | --- | --- |
| 持续对话 | 发消息、查看流式回复和历史 | 在同一段对话继续追问 |
| 模型偏好 | 在「我的」选择对话模型 | 读取同一账号的选择 |
| 任务 | 在「任务」安排、查看进展与结果 | 查看和管理同一批任务 |
| 附件 | 原生端提供照片图库、文件选择和设备支持时的拍照入口 | 文件及对话结果归属同一账号 |
| Hymio UI | 原生卡片、选项和输入组件 | 同一份界面数据由 Web 组件呈现 |
| 执行记录 | 在「我的 → 工作记录」检查过程 | 查看同一执行记录 |

## 离开屏幕后，工作如何继续

切到其他应用或关闭网页，不会取消服务端已经接纳的工作。iOS 回到前台时会恢复凭据、读取本机缓存并补齐事件，各个客户端分别记录自己已经收到的位置。

**待发送和已接纳要区分。** 尚未送达的消息要等连接恢复；已经接纳的工作由服务端推进。这个过程不代表 iPhone 在后台持续运行 Agent，也不代表已经支持推送通知。

## 使用前确认

iPhone 和 Web 应连接同一套 Hymio 部署，并登录同一账号。连接到不同后端、不同账号，内容不会自动合并。当前原生端支持账号密码登录，浏览器 OIDC 登录、语音输入、推送和原生手机控制仍待实现。

从[安装与启动](./getting-started)开始；已部署服务的局域网访问要求见[配置与部署](./configuration#局域网与-ios)。
