# 云设备与管理

Hymio 区分**客户端**与**执行设备**。Web 和 iPhone 承载对话；获得授权的云电脑提供 Bash、浏览器与桌面操作环境。

## 真实案例：手机和 Web 都在线，为什么还没有云电脑？

我们先用同一演示账号登录 iPhone 和 Web。「我的设备」已经显示两端在线，但 Web 明确提示“当前没有云电脑。需要使用时，请联系管理员开通；对话不受影响”。这说明账号登录和消息同步正常，并不等于已经分配执行环境。

这时仍可以在手机继续整理清单、提问和查看结果。如果要让 Agent 在远程桌面上浏览网页或执行命令，需要先完成资源授权，再发起设备请求。

## 真实案例：先开权限，不立即创建电脑

我们在独立测试数据库运行同一套 Backend 和管理平台，为「旅行演示用户」开通 Daytona 权限。管理页变成“已授权”，云主机仍是 0 台；开通权限这一步没有创建云电脑。

<DocFigure src="/screenshots/hymio-admin-grant.png" caption="实际保存授权后的管理统计：已授权 1 位，云电脑 0 台；取景不包含账户标识。" />

**接下来怎么用**：用户从 iPhone 或 Web 交代需要远程环境的工作，服务端检查授权与容量后才准备环境。准备成功后，“我的设备”才会出现云电脑。本次案例验证到授权保存，没有把未执行的云电脑任务写成完成结果。

管理员操作见[管理平台的实际案例](./admin#真实案例-为一个用户开通云电脑权限)。

## 一个环境，三种接口

Bash、浏览器自动化和 Computer Use 指向同一个设备 ID、文件系统与桌面。浏览器截图指定页面，桌面截图捕获当前屏幕。机器地址属于私有 Provider 配置，不要求用户贴进对话。

| Provider | 当前分配上限 | 接入方式 |
| --- | --- | --- |
| Daytona | 10 台 | 托管沙箱 API / SDK |
| E2B | 20 台 | 已有 Provider 兼容 |
| 自管 ECS | 1 台 | 主机侧 HTTPS 设备 API |
| 云手机 | 未开放 | 为后续接入保留 |

这是 Hymio 的分配上限，不是供应商价格或账户额度；供应商自身的配额与计费仍然生效。

## 先授权，再分配

新用户默认没有云设备。管理员允许账号使用某个 Provider 后，后续设备请求才会分配或恢复环境。关闭权限不删除文件。

暂停设备与结果不确定的分配仍占用容量。确认释放是独立操作：托管沙箱释放可能删除数据，自管 VM 解绑后仍在 Hymio 外部运行。

## 独立管理平台

管理平台位于 `/admin/`，独立于用户应用，管理资源授权、配额与生命周期。后端根据私有 `admin_user_ids` 校验每次操作。

本机开发管理平台：

```sh
# 在 Hymio 仓库内执行，Backend 需已启动
pnpm --filter @hymio/admin dev
```

启动成功后，使用终端显示的管理平台地址，访问该服务的 `/admin/` 路径；云部署则使用部署者提供的站点地址加 `/admin/`。文档站不提供管理平台服务。登录条件、授权流程与排查见本站[管理平台](./admin)。

## 恢复，不应消耗信任

超时不能证明操作失败。Hymio 记录未知结果并保留名额，避免重复创建电脑。Agent 应报告权限或容量限制，而不是循环修复凭据。

原生 Mac 控制与云手机属于未来接入方向，它们的归属与分配会延续这一套资源管理模型。
