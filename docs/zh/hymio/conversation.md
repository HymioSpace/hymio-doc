# 对话与客户端

每个用户对应一段持续的 Agent 对话。在支持的客户端之间切换，不需要创建新会话。

## 对话位于哪里

iOS 一级入口是 **此刻 / 对话 / 我的**。任务、记忆、连接、设置、设备与诊断都属于“我的”子页面。
Web 与 Desktop 使用带标签侧栏和更宽内容区。不同平台的外壳可以不同，但对话、账号与业务记录
始终是同一套。


## 真实案例：从手机的旅行清单接着聊

在原生 iOS 发起两天旅行打包清单请求后，我们用同一账号打开 Web，直接追问「把刚才那份清单压缩成四行，每行不超过十二个字」。原来的请求、中文回复、Web 追问和精简结果都出现在同一段对话里，手机也收到了后续内容。

## 发送和查看消息

在输入框中输入内容，按需添加附件后发送。客户端先显示本地待发送消息，再等待后端接纳。ACK
表示输入已接纳，不代表模型已经处理完成。iOS 发送后会收起键盘。

助手回复逐步显示。工作过程收纳中间文本、模型提供的思考内容和工具活动，需要时可以展开。
完成后的最终回复保留在工作过程外。

### 锚定与空白

滚动锚点指向消息末尾的 1 点透明标记；它不制造可见空白。内容高度、键盘和外壳安全区变化后，
客户端等待布局完成再校正到底部，而不是保存一个可能过期的滚动偏移。工作详情展开时暂停自动跟随，
内容从所属行继续向下增长；只有用户主动拖动才停止跟随，系统布局变化不会被误判为用户滚动。

用户可以主动向上滚动离开尾部。此时新 token 只更新已有消息，不会把视口拉回；回到底部后恢复
跟随。iOS 在“本地消息已显示、首个回复尚未到达”时也必须让已发送消息可见，不能显示整屏空白，
也不能在键盘收起或探索内容增长时来回跳。

## 连接与执行独立

关闭 Web、Desktop 或 iOS，不会取消 Oath 已接纳的工作。重连后客户端从自己确认过的事件游标继续接收，离线边界区分补发内容和实时输出。

消息发送失败时，先看它的发送状态。接纳之后断线，与发送被拒绝是两种情况。协议通过稳定 command ID 识别重试，避免把同一个请求当成新消息。

## 历史与渲染

近期对话通过快照加载，更早的消息按需读取，实时事件从快照 checkpoint 之后开始。每个客户端窗口独立维护投递进度。

实时正文先进入小型显示缓冲，展示速度独立于网络分块；历史内容直接显示。这个缓冲只影响视觉，
不改变事件持久化、ACK 或任务状态。

### 工具活动

默认工作视图展示 Agent 所说的动作。Oath 的每次工具调用都必须带语义 `description`；客户端优先
显示这句话，工具名只作为次要短标签。“执行命令”等通用文案或原始 JSON 不能替代有效描述。

进入某个 Agent 或 Trace 后，可以继续查看工具、状态与有界结果。原始参数和技术 payload 只在更深
的检查界面出现。

## 不同客户端

| 客户端 | 交互方式 |
| --- | --- |
| Web / Desktop | 带标签侧栏、键盘输入、截图粘贴与较宽任务 inspector |
| iOS | 此刻 / 对话 / 我的、流式对话、Hymio UI 卡片、照片/文件输入与图片查看 |
| 管理平台 | 独立登录与资源管理，不是对话客户端 |

跨设备接着用的实际案例见[多端互通](./ios)。

## 排查问题

可以在独立 Trace 页面查看执行详情。它是技术视图，本端已同步事件不等于完整服务端 Journal。任务状态与工具终态也不同：工具成功之后，Agent 的后续步骤仍可能失败。
