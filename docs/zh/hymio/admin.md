# 管理平台

管理平台是给 Hymio 部署管理员使用的独立 Web 应用，用于开通云电脑权限、查看容量和管理设备生命周期。普通用户在主应用对话，不需要进入这里。

## 真实案例：为一个用户开通云电脑权限

**场景**：一位用户在 iPhone 上正常对话，但还不能让 Agent 使用云电脑。管理员要开放资源使用权，而不是把供应商密钥发给用户。

这次使用实际 Backend、实际管理前端及独立测试数据库，操作对象为「旅行演示用户」。演示没有改动运行中用户的权限，也没有申请付费云电脑。

1. 用测试环境中已配置为管理员的产品账号登录管理平台。
2. 在「用户权限」找到「旅行演示用户」，此时状态为“未开通”。
3. 选择已配置的 Daytona，点击「开通权限」。
4. 界面提示“权限已更新”，该用户变成“已授权”，并增加一条 `grant` 操作记录。
5. 检查云主机仍为 0 台：授权保存成功，但尚未创建执行环境。

<DocFigure src="/screenshots/hymio-admin-grant.png" caption="实际管理统计：已授权 1 位，云电脑 0 台；不展示账户标识区域。" />

用户之后可以在 iPhone 或 Web 发起需要云电脑的工作。设备分配仍会检查容量与 Provider 状态，不能把这里的“已授权”当成任务已经执行完成。

## 先认识这些术语

| 术语 | 含义 |
| --- | --- |
| 管理员 | 产品用户 ID 已加入私有配置 `admin_user_ids` 的账号。不是另建一套管理员密码。 |
| 资源授权 / Grant | 允许某个用户使用某个云电脑 Provider。授权后，用户的设备请求才可以分配环境。 |
| 容量 / Capacity | 可分配设备的上限和已占用数量；供应商额度仍单独生效。 |
| 设备生命周期 | 分配、暂停、恢复和确认释放等操作。暂停不等于释放容量。 |

## 如何访问

部署者提供管理平台的站点地址，入口路径为 `/admin/`。这是 Hymio 应用的入口，不能在文档站域名下打开。

本机开发时，先启动 Hymio Backend，再在 Hymio 仓库执行：

```sh
pnpm --filter @hymio/admin dev
```

使用启动日志显示的地址进入 `/admin/`。前端开发服务器会把 `/auth` 和 `/admin/api` 请求代理到 Backend；只启动前端无法完成登录和管理操作。

## 首次登录与授权

1. 在主应用注册产品账号，取得该账号的产品用户 ID。
2. 部署者把管理员的 ID 加入私有 `admin_user_ids` 配置，按[配置与部署](./configuration)重启服务使其生效。
3. 在管理平台使用同一个产品账号登录。
4. 为需要云电脑的用户开通相应 Provider 的资源权限，再让用户请求设备。

管理权限由 Backend 对每个操作校验；前端显示的身份不能代替服务端授权。供应商凭据由部署者保存在私有配置中，不由普通用户提交到对话。

## 管理设备时注意什么

- 暂停设备和结果未知的分配仍占用容量。
- 超时后先查询现有操作，避免重复创建电脑。
- 释放托管沙箱可能删除文件；自管虚拟机解绑后仍可能继续运行，需要在 Hymio 之外维护。

## 无法访问时

| 现象 | 检查 |
| --- | --- |
| 页面无法连接 | 平台服务是否启动、访问的是否是部署者提供的地址。 |
| 能打开但无法登录 | Backend 和身份服务是否可达；开发代理或云端同源路由是否正确。 |
| 登录后没有管理权限 | 当前产品用户 ID 是否在已生效的 `admin_user_ids` 中。 |
| 用户仍无法使用设备 | 是否开通了对应 Provider，容量是否用尽，供应商配置是否可用。 |

接口见 [HTTP API：管理 API](./api#管理-api)，设备边界见[云设备与管理](./devices)。
